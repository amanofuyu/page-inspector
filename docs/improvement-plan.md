# Page Inspector 后续改进方案

目录说明：项目已迁移为 monorepo，本文涉及的扩展源码相对路径均相对于 `apps/extension/`；当前运行命令和验证结果以根 README 与验证记录为准。

本文记录本次实现依据的改进方案。实现与验证结果见 [验证记录](validation.md)。

## 目标与范围

将现有工具完善为能够准确读取、解释和查看 Nuxt 页面初始 payload 的浏览器扩展。继续使用 WXT、Vue、TypeScript 和现有样式体系。

- 第一版兼容目标：Chrome、Edge；Nuxt 3/4 使用 JSON payload 的页面。支持范围以固定版本样本验证结果为准。
- 默认展示首屏 SSR／预渲染 payload，标明来源、采集时间和所属文档；读取 `serverRendered` 等标记，避免将所有 payload 都标记成 SSR。
- Firefox、多 iframe、运行时状态查看、快照对比作为后续独立扩展项。
- 站内路由切换不一定更新内嵌 payload。检测到地址变化后标明快照可能属于初始页面；当前路由运行时数据需要独立的数据来源和采集机制。

## 关键设计

### 分离采集、解析与展示

```mermaid
flowchart LR
    A[页面采集脚本] -->|原始文本与来源信息| B[后台协调请求]
    B -->|可序列化消息| C[侧边栏解析模块]
    C --> D[带类型与引用信息的展示模型]
    D --> E[数据视图与原文视图]
```

注入脚本仅采集 DOM 中的原始文本、节点属性和页面地址。后台负责目标标签页、请求协调和必要的外部数据读取。解析库在扩展自己的侧边栏环境中运行。

Chrome 扩展消息采用 JSON 序列化，因此传递还原后的 `Map`、`Set`、`BigInt` 和循环引用会带来损失或失败。原始文本可以避免这一问题；也能避免向 `executeScript.func` 引入不可携带的外部依赖。[Chrome 消息文档](https://developer.chrome.com/docs/extensions/develop/concepts/messaging#serialization)、[脚本注入文档](https://developer.chrome.com/docs/extensions/reference/api/scripting)

### 采用标准解码器，保留类型信息

用 `devalue.parse` 处理基础序列化格式，另外实现 Nuxt 内置类型的查看器适配器。Nuxt 官方也通过 devalue 与自身 reviver 配合还原 payload。[Nuxt payload 源码](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/composables/payload.ts)

- `Ref`、`ShallowRef`、`Reactive`、`ShallowReactive`：展示其值，保留包装类型元信息，不需要建立响应式运行环境。
- `EmptyRef`、`EmptyShallowRef`：正确解释 `false`、`0`、空字符串、`null`、`undefined`、`0n` 等值。
- `NuxtError`：保留可查看的错误字段；其他内置标签按样本逐项适配。
- 自定义或未知类型：明确报告类型不支持，提供原始文本；能够局部解析时保留类型标记，不能局部解析时回退原文，不猜测类型语义。
- 页面自定义 reviver 和会触发额外请求的运行时行为不直接执行。

Nuxt 包装类型的解释以官方实现为依据，但查看器保留的是数据含义与类型标签。[Nuxt reviver 源码](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/plugins/revive-payload.client.ts)

展示模型应显式区分对象、数组、特殊值和引用。循环引用显示目标路径或节点编号，`Map` 展示键值条目，`Set` 展示成员，`BigInt` 保留类型。原始文本始终可查看和导出。普通 JSON 导出需要说明特殊类型的转换规则。

## 阶段一：修复解析链路，形成可验证的基础版本

### 改动

1. 将 `crawl(url?)` 改为带 `tabId` 和 `requestId` 的采集协议，移除未使用的 URL 参数。
2. 拆出页面采集函数，返回原始 payload 文本、来源节点、页面地址和文档身份信息。
3. 将解析逻辑从注入函数移到独立纯函数模块，用 devalue 与 Nuxt 适配器替换手写索引解析。
4. 增加展示转换模块，处理特殊类型、重复引用和循环引用；保留原文入口。
5. 将结果区分为成功、部分可用、未找到、格式不支持和失败；失败包含具体原因，取消统一返回 `null` 的做法。
6. 界面补齐加载、失败、重试、手动刷新状态；先沿用现有文本展示方式。

### 验收

- 普通对象、数组、重复引用及现有可用样本不回退。
- 修复已验证问题：单元素 Set 被拆成值、EmptyRef(false) 变成字符串、Date 变成数组、NaN 字段丢失、循环引用导致展示失败。
- 补充空／多元素 Set、Map、RegExp、BigInt、空值、数组空洞和 Nuxt 响应式包装的测试。
- 无 payload、畸形文本、未知类型和禁止注入的页面均有明确结果，保留能够取得的原始文本。
- 解析／格式化模块可脱离浏览器测试，消息链路仅传普通元信息和原始文本。

## 阶段二：解决页面归属与刷新问题

### 改动

1. 侧边栏绑定所在窗口的活动标签页，监听相关标签页激活、关闭与文档加载完成事件；后台按显式 `tabId` 采集，避免重新查询时选错页面。
2. 使用 `tabId + documentId + requestId` 校验响应。快速切换页面时丢弃旧结果，清理已关闭页面的临时数据。
3. 合并短时间内重复触发的请求；保留手动刷新入口。首次未取得节点时，只在文档加载阶段做有界重试。
4. 地址变化时检查文档身份与数据来源。完整导航重新采集；同文档导航标记快照可能过期，保留原始页面信息。
5. 首次观察可能发生在 SPA 已经导航之后；无法确认快照路由时显示来源不确定，不能把采集时 URL 当成原始 SSR 路由。

### 验收

- 从页面 A 快速切到 B，A 的慢响应不会覆盖 B。
- 刷新、跳转、切换窗口和关闭标签页后，结果归属与侧边栏一致。
- 非 Nuxt 页面明确显示未检测到数据，不残留上一页内容。
- SPA 路由切换后，不把初始 payload 宣称为当前路由的最新状态。
- 后台重启后可重新采集，不依赖后台内存永久存活。

## 阶段三：扩展数据来源与查看能力

### 改动

1. 兼容 `#__NUXT_DATA__` 与 `[data-nuxt-data]`，存在多个应用时按应用分别查看，避免合并不同应用的数据。
2. 支持节点 `data-src` 指定的外部 JSON payload：相对 URL 按页面地址解析，使用现有主机权限读取，保留内嵌与外部原文，分别解析后按已验证规则合并。
3. 外部请求设置超时和取消，处理响应状态、重定向、格式及体积；凭证策略通过同源、CDN、需要登录的测试样本确定，不把读取 cookies API 作为前提。
4. 外部资源失败时继续展示内嵌结果，并标明数据不完整。外部数据是采集时重新取得的资源，记录 URL 与获取时间；无法确认版本一致时不能宣称它就是原始 HTML 对应的精确快照。
5. 增加 `data`、`state`、错误、其他字段和原文视图；包含 `once`、`path`、`serverRendered` 等元信息。独立运行时配置的读取另列兼容范围。
6. 引入树形查看，支持逐层展开、键和值搜索、复制字段路径、复制值、导出原文和展示数据。

Nuxt 官方支持外部 payload 并合并内嵌、外部与运行时全局数据；本阶段覆盖可读取的内嵌和外部数据，显示覆盖范围。[Nuxt 数据来源处理](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/composables/payload.ts)

### 验收

- 内嵌、外部 JSON、混合来源、多应用、404、超时、登录重定向均有样本。
- 来源合并顺序可验证，外部失败不会抹掉已经读取的数据。
- 不同类型、循环引用及重复引用在树形视图中可辨识。
- 原文导出保持原始文本；展示数据导出明确类型转换规则。
- 空的 `data` 与完全没有检测到 Nuxt payload 使用不同提示。

## 阶段四：性能与发布整理

### 改动

1. Shiki 按需初始化并复用，只加载实际使用的语言；大数据默认使用折叠树，避免整份高亮和一次创建全部节点。
2. 用 100 KB、1 MB、10 MB 样本记录解析、搜索、展开和高亮耗时，再确定降级阈值；超大输入提供明确限制与原文操作入口。若解析阻塞明显，再迁移到 Worker。
3. 清理没有调用的 `cookies`、`debugger` 权限，校验生成后的 manifest。第一版保留支持跨标签页自动读取所需的主机权限；按站点授权作为独立产品选项。
4. 修正 `web-ext.confg.ts` 的命名或删除重复配置；补充中文 README、兼容矩阵、限制、开发和构建说明。
5. 将当前实际执行构建的 `test` 脚本改成含义明确的名称，加入真正的单元测试入口，统一类型检查与构建检查。
6. 移除无效主题广播，确保主题存储能够正确区分未设置与合法的假值；核对相关代码的实际调用范围。

Chrome 的 `activeTab` 是临时权限，不能直接替代所有自动读取场景需要的站点访问权限。[Chrome 注入权限要求](https://developer.chrome.com/docs/extensions/reference/api/scripting#manifest)

### 验收

- 大 payload 不会因为全部展开或整份高亮导致侧边栏长时间失去响应；限制和降级行为有记录。
- 类型检查、lint、目标浏览器构建及有意义的单元测试通过。
- manifest 中每项权限都有对应功能，README 与实际支持范围一致。

## 建议的代码划分

保留现有项目结构，按职责逐步拆分，避免一次重构全部辅助代码。

| 文件或目录                                | 建议职责                               |
| ----------------------------------------- | -------------------------------------- |
| `entrypoints/background/message/crawl.ts` | 协调采集、外部读取和错误返回           |
| `libs/messaging.ts`                       | 采集请求、来源元信息和可序列化结果协议 |
| `features/nuxt/collect.ts`                | 可独立注入的 DOM 采集函数              |
| `features/nuxt/parse.ts`                  | devalue 解码与 Nuxt 类型适配           |
| `features/nuxt/format.ts`                 | 带类型、引用与路径的展示模型和导出转换 |
| `features/nuxt/types.ts`                  | 采集来源、诊断信息和展示节点类型       |
| `composables/useInspection.ts`            | 当前标签页、请求状态、刷新与结果失效   |
| `features/inspector/`                     | 数据视图、来源信息、空态与错误展示     |
| `tests/fixtures/nuxt/`                    | 固定版本、脱敏的 payload 样本          |

## 测试与实施顺序

- 优先为解析正确性、信息保留、来源合并、异步结果竞争编写单元测试；保留真实固定版本样本，避免只测试同一依赖生成的数据。
- devalue 不保证所有版本间的格式兼容，安装新版不能替代 Nuxt 版本样本验证。[devalue 项目说明](https://github.com/sveltejs/devalue)
- 安装新增依赖前联网查询最新版本，再核对与项目工具链的兼容性并锁定解析结果。
- 在 WSL 中运行 Node 相关命令前显式加载 nvm。
- E2E 执行前先征得用户确认；本方案不视为已经获得 E2E 授权。
- 建议按上述四阶段分别提交。第一轮实施阶段一和阶段二，以“解析可信、页面归属正确、失败可解释”为交付标准。
- 第一轮完成后再实施外部来源与树形交互。运行时数据模式与 Firefox 各自建立适配与验收范围。
