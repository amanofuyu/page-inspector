# 分析、检索关注与 DevTools 实现记录

日期：2026-09-28。首版已完成审查修复；85 项单元测试、静态检查与构建通过。用户授权后，8 项协议侧栏、24 项真实 Nuxt 和 1 项真实 DevTools 浏览器验收均通过。

## 使用流程

重新加载生产扩展 `apps/extension/.output/chrome-mv3-prod`。侧栏顶部增加「分析」「检索」「关注」，原「数据」工作区保留六个数据分类、简单搜索和原文导出。

1. 在「分析」查看每份来源的原文 UTF-8 字节、传递消息预算、摘要与解析状态。字段排名支持按估算大小、项数或路径排序；点击条目就在其下方展开局部子树，再次点击收起，旁边可直接关注。「内容分布」的长字符串、大集合和深层结构也使用相同的就地展开方式。
2. 在「检索」选择应用范围、分类和来源，添加一层全部／任一条件。相对路径从所选分类开始，`$` 表示当前应用根；例如在 data 中查询 `products[*].price`，再添加 number 类型的值大于 100。每页 50 条，最多 1,000 条；点击结果路径在当前条目内展开详情，再次点击收起，切换结果页时关闭旧详情。可复制摘要、导出本页、收藏条件和关注。查询失败在执行按钮旁显示错误，并清除旧结果；修正条件后可重新执行。
3. 在「关注」输入精确路径或使用树节点上的星标。支持别名、删除与可选查询参数作用域。刷新取得成功快照后显示首次出现、未变化、值变化、类型变化、缺失或无法确认。数组、Map、Set 的位置关注会受到重新排序影响。
4. 打开网页的开发者工具，选择「Page Inspector」。此面板固定检查该标签页；「网络」显示该 DevTools 会话观察到的请求，先记录元信息，选择记录后手动读取正文。可对照扩展重新获取内容，或将支持的响应显式作为独立 payload 查看。

树节点增加字段详情与关注按钮，复制操作仍独立。数据树、排名、检索结果和详情中的关注按钮同步显示状态：已关注为高亮实心星标／「已关注」，再次点击取消；保存期间禁用重复操作。状态按当前页面和应用范围匹配持久化规则，刷新和其他面板的存储变更会同步更新。分析与检索详情固定在所选条目内展开，同一时间保留一个展开项；切换条目、关闭或刷新后，迟到结果不会重新打开旧详情。其他入口的详情在窄侧栏放于主内容下方，在宽 DevTools 面板与主视图并排。页面继续采用磨砂玻璃、弥散渐变、微噪点和小圆角。

初始文档无法确认、应用声明标识缺失或重复时，禁止自动创建关注绑定。页面范围不匹配的规则另列；SPA 地址变化继续展示初始快照提示，不假装监听到了运行时状态。

## 公共模型与边界

| 模块                              | 职责                                                               |
| --------------------------------- | ------------------------------------------------------------------ |
| `features/nuxt/`                  | 保留来源身份、原文度量、独立解码结果与浅合并覆盖链；原有树模型兼容 |
| `features/inspection/`            | 类型摘要、结构化路径、有界图索引、共享实体与引用边                 |
| `workers/payload.worker.ts`       | 从原文建立单应用索引，运行估算、查询、局部详情和关注比较           |
| `composables/usePayloadWorker.ts` | 任务编号与快照校验、切换释放、取消和 8 秒总超时                    |
| `features/analysis/`              | 来源 SHA-256、字段独立估算、排名和默认不带业务值的分析报告         |
| `features/query/`                 | 路径解析、条件校验、通配解析、查询覆盖范围                         |
| `features/watch/`                 | 作用域、规则校验、串行持久化与会话比较基线                         |
| `features/network/`               | 真实 DevTools 句柄所有权、HAR 元信息、正文缓存、来源核对           |
| `features/inspector/`             | 侧栏和 DevTools 共用查看器、工作区和字段详情                       |

每个界面只保留当前应用／来源的一个 Worker。旧快照任务不能覆盖新快照；取消会终止 Worker，可点击「重建索引」恢复。原有树形查看仍在界面线程解码，新增分析、索引、查询和关注在 Worker 内处理；这是方案允许的渐进迁移边界，并未声称所有解析都已离开主线程。

结构化路径区分 `$["0"]` 与 `$[0]`，Map 键和值分别使用 `[map:0:key]`、`[map:0:value]`，Set 使用 `[set:0]`。复制字段路径采用该格式。旧 `page-inspector/v1` 导出保留原字段并增加可选 `fieldPath`，未改为普通业务 JSON。

来源模式可选择合并结果或单份原文。页面或应用变化后，如果原先选择的来源已不存在，会在建立索引前自动切回合并模式；仍有效的来源选择继续保留。同名顶层字段的覆盖历史保留，后代继承当前路径顶层字段的最终来源。共享对象只存一份实体，指定别名路径时沿引用边解析；常规无路径条件扫描索引实体，不无限枚举循环的所有别名。

## 计量、比较与预算

原文度量为完整采集文本的 UTF-8 字节。消息预算另计 `JSON.stringify(text)` 的 UTF-8 字节；未完整读取或未精确计量时使用未知值与已读下界，失败来源不会伪装成零字节原文。HAR 的 content.size、bodySize 与解码文本字节分别展示。

`typed-structure/v1` 以类型标记、键名、标量字面量、容器及局部引用编号进行结构估算。对象键按稳定顺序遍历；日期、正则、URL、二进制类型和 Nuxt 标签保留类型语义；循环与共享对象只展开一次。字段之间可共享同一对象，字段估算不能相加，不能当作删除字段后的网络节省量。

关注采用完整的有界类型结构编码比较，不使用预览或摘要相等来推断相等。保留 `-0`、NaN、BigInt、空洞、undefined、null、循环和别名关系；预算不足时为无法确认，旧基线保留。规则写入 `storage.local` 的独立版本键，后台串行写入避免两个界面互相覆盖；值和基线不持久化。

| 项目                     | 当前限制                                             |
| ------------------------ | ---------------------------------------------------- |
| 采集                     | 12 MiB 消息预算、16 个应用                           |
| 展示                     | 单个树 10,000 节点、60 层；每次展开 100 项           |
| 独立索引                 | 100,000 节点、100 层、2 秒软预算                     |
| 分析／查询／一批关注比较 | 每项 2 秒；达到预算显示部分或未知                    |
| 查询                     | 每页 50 条，最多 1,000 条、10 个条件                 |
| 关注定义                 | 每个精确作用域 50 条，全部定义含收藏查询最多 500 条  |
| 关注内容                 | 前次与当前的序列化比较内容合计上限 2 MiB；单批 1 MiB |
| Worker                   | 当前应用一份；单次调用含排队总超时 8 秒后终止        |
| 网络                     | 500 条元信息且不超过 2 MiB；正文 LRU 缓存 12 MiB     |

分析报告格式为 `page-inspector-analysis/v1`，不输出字段预览和解析错误原文；仍包含路径、来源 URL、类型、摘要、度量与预算，因此属性名和 URL 中的信息仍可出现。查询本页摘要导出为 `page-inspector-query/v1`，明确包含用户选择导出的结果预览。

## 请求证据与兼容性

面板使用回调形式的 `panels.create`、`network.getHAR`、`Request.getContent`、`onRequestFinished` 与 `onNavigated`，不依赖 Chrome 151 起的 Promise 变体。Manifest 增加 `devtools_page`；权限仍为 storage、scripting、sidePanel 和 HTTP／HTTPS 主机访问，未添加 debugger、webRequest 或 cookies。

只有声明的完整外部 URL、当前文档身份、HAR 页面／导航时间及完整响应文本均可核对时显示「内容已核对」。其余分为来源候选、手动业务候选或无法关联。相同 URL 的不同请求保留，HAR 与实时事件的重复导入按完整时间等信息核对，歧义会阻止确认。

正文大小未知默认不读取；已知超大先拒绝，读取后再次核验。base64 按 UTF-8 文本解码；304、缓存、重定向和不可读正文不会被当成空 payload。`getContent` 无法流式限制浏览器回调前的内存分配，12 MiB 约束的是读取判定及扩展内的正文缓存。

导航默认清理旧记录；请求归属通过采集文档身份与 HAR 页面导航起点核对，允许毫秒精度舍入，不使用导航通知的到达时间猜测。证据不足的请求保留并标为「页面归属未确认」，不会因加载耗时超过固定阈值而丢失。保留记录选项按已确认的页面代次展示且仍受总预算限制。关闭面板清理监听、正文任务、缓存和 Worker。响应快照与原页面采集独立：即使原页面无数据或采集失败，合法响应仍可查看、分析和检索；进入响应时清除旧分类及搜索条件，返回页面快照时恢复先前的应用选择。响应不自动建立关注作用域。此能力无法看到服务端 SSR API 调用，也不会从 Nuxt 的 payload key 推导确定的接口来源。

依据：[Chrome 网络 API](https://developer.chrome.com/docs/extensions/reference/api/devtools/network)、[Chrome 面板 API](https://developer.chrome.com/docs/extensions/reference/api/devtools/panels)、[WXT DevTools 入口](https://wxt.dev/guide/essentials/entrypoints#devtools)、[HAR 1.2 字段定义](https://github.com/ahmadnassri/har-spec/blob/master/versions/1.2.md)。Chrome／Edge 116+ 是兼容目标；本轮尚未验证实际 Chrome 116 或 Edge。

## 验证记录

环境：WSL Linux，Node 22.23.3，Vitest 5.0.2，WXT 0.21.4；未安装新依赖。

- 85 项单元测试通过，覆盖原功能、原文口径、来源覆盖、循环／共享图、转义路径、空洞、类型条件、独立索引、关注基线、作用域、并发规则保存、初始化竞争、Worker 取消和迟到消息、固定标签页以及网络关联与预算。
- `pnpm lint`、三个应用的 `pnpm typecheck` 和扩展生产构建通过。
- Nuxt 3／4 的 SSR、static-inline、static-external 六组产物构建完成，新增 `/features` 页面。SSR 页面通过 `?version=2`、`?version=3` 生成类型变化、数组换序和字段删除；所有配置包含长中文、emoji、共享数据、特殊属性名和 12,000 个字段。
- 网络按钮用于 SSR 动态服务的同 URL 多次响应、重定向、gzip 和缓存请求；静态部署没有动态 Nitro API，外部 payload 按钮可用于 static-external 配置。
- 浏览器专项实测全部通过：8 项协议侧栏、六组配置共 24 项真实 Nuxt、1 项真实 DevTools。DevTools 探针覆盖面板注册、固定标签页、同 URL 多次请求、真实正文读取、独立 payload 查看与导航清理，并用服务端延迟 2.2 秒验证慢主文档仍保留。
- 回归修复覆盖存储键序变化后的关注路径与作用域限额、业务数组和标量的严格比较、装箱标量展示／导出，以及无原型对象键序变化的关注误报。浏览器读取的既有关注规则无需迁移。

## 浏览器验收

本次会话已获用户明确授权，三个套件均已实测通过。完整重建并验收的入口为：

```bash
export NVM_DIR="$HOME/.nvm" && . "$NVM_DIR/nvm.sh"
nvm use
pnpm test:e2e:all
```

也可分别运行 `pnpm test:e2e`、`pnpm test:e2e:nuxt`、`pnpm test:e2e:devtools`。本轮分别通过 8 个协议侧栏用例、六组配置共 24 个真实 Nuxt 用例，以及 1 个真实 DevTools 接入探针。浏览器使用 Playwright Chromium 153.0.8010.12；产物按 `test-results/protocol/`、`test-results/real-nuxt/`、`test-results/devtools/` 隔离，真实 Nuxt JSON 报告为 `test-results/nuxt-results.json`。

DevTools 用例只连接浏览器自动创建的真实开发者工具和扩展面板，不通过普通扩展页模拟 API。隐藏页签通过 DevTools 自带快捷键逐项切换，等待浏览器创建真实面板目标；不依赖当前窗口宽度下可见的页签。正文断言等待实际预览，截图由 DevTools 顶层目标获取。

人工验收步骤也保留：加载扩展，打开 Nuxt SSR `/features` 的 DevTools → Page Inspector → 网络；连续请求业务 JSON，检查两条不同响应；检查 gzip、重定向和缓存；再在外部预渲染页面核对实际 payload 响应。切换普通标签页不应改变面板目标；新文档默认清空旧请求；关闭面板后侧栏仍可独立重新采集。另用 Chrome 116 和当前 Edge 检查回调 API、布局及正文能力。

精确 devalue 原文字节归因、递归／正则查询、按业务 ID 关注、运行时状态监听、服务端追踪和原生 Network 精确行跳转保持为后续增强，没有混入本轮首版承诺。
