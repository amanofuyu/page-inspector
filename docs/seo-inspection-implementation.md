# SEO 检查首版实现记录

日期：2026-09-29。对应 [方案](seo-inspection-plan.md) 的前两步：可靠来源链路与独立查询闭环。

## 使用流程

1. 在侧栏或 DevTools 打开「SEO」，立即读取当前主文档。普通 HTML、纯 CSR 和没有 Nuxt payload 的页面均可使用；不随 Nuxt 应用选择或独立 payload 响应切换。
2. 在 DevTools 点击「刷新并捕获 HTML」建立实际导航响应基线；晚打开 DevTools 时，浏览器可能未保留旧正文，此操作会刷新被检查页面。
3. 侧栏独立打开时可点击「读取参考 HTML」。这会重新请求当前地址，参考响应与当前 DOM 的差异不会被标为确定的客户端新增／删除。
4. 用「差异／HTML／DOM／问题」切换查看方式，再按名称或值、分组、来源状态、空值／缺失／多值筛选。字段在当前行下方展开，支持复制标签或字段对比。
5. 导出 JSON 或 Markdown 报告，保存来源、采样时间、文档身份、完整性、已采集字段、差异与规则结果。报告仅覆盖实际采集范围；操作反馈共用悬浮 toast。

## 字段与来源

字段包括 title、全部有名称的 meta、html lang、base、canonical、hreflang、OG／Twitter、head 与 body 的 JSON-LD，以及 H1。保留重复项、原始值、位置和标签片段。URL 根据各自 HTML／DOM 的 base 解析，不丢弃查询参数。

JSON-LD 保留原文；结构对比忽略对象键顺序、保留数组顺序，展示根对象及 `@graph` 中的 `@type`。语法错误单独提示；嵌套超出预算属于部分结果，不会误报语法错误。不请求远程 `@context`，不执行采集到的脚本。

JSON-LD 在列表与详情中以两空格缩进展示，HTML／DOM 两侧采用相同排版。格式化只调整字符串以外的空白，保留数字精度、键顺序、重复键和转义；无效或截断数据回退原文。列表最多预览 8 行／240 字符，详情保留 16,000 字符上限；复制标签和报告仍使用采集内容。

HTTP 状态、X-Robots-Tag、Content-Type 和 Link 单独标为响应信息。Link canonical 提取为独立字段，相对地址以响应 URL 解析，不使用 HTML base；带 anchor 的项只保留原始响应头，不归为本页规范地址。引号内及 URI 中的逗号／分号不会被误拆，重复 rel 采用首项。[RFC 8288](https://www.rfc-editor.org/rfc/rfc8288.html)

| 来源                     | 可作出的结论                                                       |
| ------------------------ | ------------------------------------------------------------------ |
| 已关联的导航响应         | 与同一文档、同一 URL 的 DOM 对比：初始已有、运行后新增／修改／删除 |
| 当前 DOM                 | 采样时的实际标签；缺少基线时标记来源未确认                         |
| 重新请求的参考 HTML      | 只作参考对比，即使地址相同也不提升为导航响应                       |
| 截断、超预算或身份不一致 | 保留已知字段；不从未采集到的数据推断新增或删除                     |

初始 HTML 可能来自 SSR、预渲染、静态文件或缓存，不能单凭 HTML 证明服务器实时渲染。运行后差异也不承诺归因到某个框架或业务脚本。标题和重复标签按同类出现顺序比较，H1 不追踪节点身份。

## 文档关联与生命周期

复用现有 NetworkSession，按需读取文档正文。检查文档请求类型、当前及初始 URL、documentId、Navigation Timing 起点、HAR 页面起点、唯一候选、完整 HTML 响应状态、正文大小与可读性。当前 Chromium 的 HAR 起点精度为毫秒，允许不超过 1ms 的舍入差；缺少证据不确认来源。204／205／206／304 等不建立完整文档基线。

HAR 没有提供可用于本功能的可靠主框架标识，因此页面含 iframe／frame 时保守拒绝确认实际主文档来源，仍可查看 DOM 或参考 HTML。HTTP 重定向后的最终文档必须独立满足同一套身份检查。

每次采样前后再次校验文档身份。切换标签页、完整导航或 URL 变化立即清除旧比较；异步任务有代次标识，迟到结果不发布。当前版本通过已有 tabs 更新事件加显式采样处理路由变化，不宣称覆盖所有同 URL 路由会话或 BFCache 细节。

同一文档手动重读保留旧快照和筛选，成功反馈至少持续 400ms；失败时提示仍显示上次数据及时间。支持取消，读取与等待刷新均有 20 秒上限。切换工作区或卸载会取消待发布任务并释放监听。

后台仅接受扩展面板消息，只有 DevTools 可以写入已关联基线，写入前再次验证目标文档 URL 和导航起点。侧栏重新读取时获取同一身份的缓存。缓存只驻留内存，最多 4 个标签页、单份 6 MiB、总计 12 MiB、10 分钟过期，导航和关闭标签页清理，服务进程重启后消失。

## 解析与预算

安装前查询 npm registry，新增精确依赖 `parse5@8.0.1`；锁文件仅增加该依赖，既有 Nuxt 依赖图保持原状。HTML 在可终止 Worker 中解析，不借助隐藏 DOM 加载资源。[parse5 解析接口](https://parse5.js.org/functions/parse5.parse.html)

- HTML 正文最多 5 MiB，参考请求流式限额；解析 Worker 超过 8 秒终止。
- 每次最多扫描 100,000 个节点，DOM 扫描预算 250ms，采集文本消息最多 2 MiB。
- 元信息最多 2,000 条，标题最多 10,000 条，普通字段 16,384 字符，单个 JSON-LD 1 MiB 字符上限并受总消息字节预算约束，JSON 结构深度最多 100。
- 列表先显示 50 项，详情原文先预览 16,000 字符；复制与导出包含完整已采集内容，不包含超预算被舍弃的部分。
- 参考请求带凭证、不跟随重定向，支持 BOM、响应头 charset 和前部 meta 编码声明。登录状态、SameSite、缓存、语言或请求头可能与页面导航不同，不承诺重放导航上下文；重定向或非 HTML 响应失败时保留 DOM。

没有新增浏览器权限。仅按需读取 SEO 有关响应头，不展示请求 Cookie 或 Set-Cookie；采集内容不上传。所有标签以文本渲染，不自动加载分享图片。

## 已实现规则与后续范围

当前规则覆盖完整扫描中的 title／description 缺失、空值、重复，HTML／HTTP canonical 冲突、无效 canonical、JSON-LD 错误、canonical 运行后修改、noindex 变化和 HTTP 状态／索引规则。故意 noindex 只作为信息或需核对项，不直接判成错误；没有 SEO 总分或收录保证。

布局首版合并为四个查看方式与分组筛选，没有实现方案中的所有快捷预设和额外总览子页。标题展示文档顺序，不做完整大纲树；JSON-LD 提供结构等价比较和双方原文，没有逐属性差异树。筛选保存在当前面板内存中。

持续 MutationObserver、暂停／恢复观察、同 URL 路由会话、时间线、历史快照、图片 alt、完整爬虫规则解释、富结果验证和跨页面审计仍属后续阶段。缓存／Service Worker 只能证明收到的文档内容，目前没有额外展示它们各自的来源标志。

验证结果见 [验证记录](validation.md)。
